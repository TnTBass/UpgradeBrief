# Component advisory recovery

The November 7, 11 and 13 catalogue failures exposed three gaps: discovery stopped before saving useful evidence, component patch changes had no maintained semantic handler, and a successful repair workflow could mean only that an investigation issue had been created.

## Acceptance and boundaries

The maintained Linux-kernel helper-appliance handler recognizes the vendor's impact-statement structure and checks the complete remaining article against a reviewed prose envelope. It extracts affected product families, CVE and score, appliance kernel, separate Windows private-fix prerequisites, filenames and checksums, recovery-media delivery, and the VRO-to-embedded-VBR relationship.

Supported transitions are first classification of this recognized advisory format, a pending private fix becoming available, the documented recovery-media delivery progression, and explicitly adding the known VRO 13.1 relationship. An available patch identity cannot silently change or disappear. Changed CVEs, unexplained prose, negations, unknown products, mismatched component builds and removed coverage remain blocked. A prerequisite build is never assigned as a fixed release.

The handler produces reviewed data only. Source fingerprints bind it to the captured article. Scope transitions additionally require the matching parsed component model and previous accepted scope; changing only a fingerprint is insufficient. All affected data and provenance are rebuilt through live refresh. Existing source re-fetch, complete verification, exact-commit publication, and public catalogue hash checks remain required.

## Evidence and isolation

Discovery records normalized source text before checking scope and waits for all source requests to settle. Errors retain structured article IDs, previous and observed scope, and findings. New articles appear as source reviews rather than accepted baseline captures.

Recognized scope additions join both the old and new owners' dependency groups. Pending reviews retain those groups, preserving their old findings, timestamps and evidence. Unaffected groups can refresh. Unrecognized scope is still a global stop; first publication of a new advisory is atomic. Feed metadata changes alone no longer merge all groups, while changed global KEV/lifecycle inputs still do.

A committed partial refresh updates the review artifact's base identity only after verifying that the clean checkout and snapshot match the refresh result. Repair can therefore resume against the actual published partial-refresh commit.

## Broader proposals and reporting

Unsupported source changes can receive a bounded Workers AI review proposal containing exact source quotes and interpretations. These proposals use the existing durable reservations, limits and cache. They cannot authorize a data change. Over-budget excerpts are not silently truncated, and unknown semantics remain unresolved.

Repair publication records recovered, needs-review or retained outcomes. Only a matching verified deployed commit and catalogue hash produce recovered. A blocked or unapplied repair exits unsuccessfully after persisting the investigation and artifact; creating an issue cannot produce a green recovery result.

## Regression coverage

The historical fixture contains the captured November 6, 10, 11 and 12 article revisions used to reproduce the three incidents. Tests exercise candidate generation without accepted-state mutation, complete discovery evidence, reviewed scope transitions, unaffected-product refresh, exact AI quote validation, durable review-proposal caching, and truthful publication outcomes. Negative cases include extra CVEs, product substitution, changed patch checksums, removed products, changed prerequisites and unsupported source guidance.

The current KB4966 repair is generated through the same maintained handler and adds conditional VRO coverage while retaining separate component-patch verification.
